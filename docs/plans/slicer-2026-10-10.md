# A managed slicer

*Decided with the owner on 2026-10-10, one question at a time, while the loop
from a picture to a print was built ([ui-flows-2026-10-08.md](ui-flows-2026-10-08.md)).
Today a person slices elsewhere and brings G-code back through the Print
card's file box; this keeps the loop in the page. Its fetches are drafted
into the personal-data record before the code that makes them lands, and
its licence disposition goes to the licence review, as OpenSCAD's did.*

## Decided

- **OrcaSlicer, behind a slicer interface.** A slicer is a module, as a
  firmware toolchain is: it says what it slices, finds its binary (an
  environment variable, then the tools dir, then `PATH`; `none` means none),
  installs it, and turns a slice into steps. OrcaSlicer's command line is the
  first module; another slicer is a module added, and the owner can switch.
- **Installed by apothecary**, as OpenSCAD is: a pinned release from its
  publisher, checked before it is opened, into the tools dir, on Linux, macOS
  and Windows, with a clear refusal where a platform is not served. A pin
  moves only in a commit that re-runs the real install and a slice.
- **The printer's profile is kept with the printer's part.** printer_1's
  profile lives with the `ender3` part, starting from OrcaSlicer's Creality
  Ender-3 profile and holding what the bench measured (the bed's offset among
  it).
- **Print settings come from the part.** A part's or a made piece's print
  settings are what it declares -- the *print settings declared* check
  `apothecary problems` already lists -- and the printer's defaults fill the
  rest. Slice says which value came from where.
- **Slice is a step of the page**: from a part or a made piece, its G-code
  for the pinned printer, kept where the Print card's file box keeps a file,
  so Print follows Slice without leaving the page.

## Open until built

- Where the G-code and its slice record are kept, and how long.
- How a part declares its print settings, where none do yet.
- The licence review of OrcaSlicer (AGPL-3.0), run as a binary and never
  linked.

## Decided after the server side

Asked of the owner on 2026-10-10, after OrcaSlicer was installed and a part
and a made piece were sliced for real:

- **The bed.** What the bench measured -- the bed 2.34 mm out of level, and
  the probe's offset, which the firmware applies when it homes -- is held in
  the printer's profile with its source, and adds nothing to the G-code. The
  start of a print is to be composed from modules as they are wanted: using
  the stored mesh, probing each print, and a measured first-layer offset are
  stubs for now.
- **Filament** is the printer's one filament (Creality Generic PLA), named in
  its profile; choosing another is a filament module, stubbed for now.
- **Made pieces** slice with the printer's values; a word declaring print
  settings for the pieces made as it is a stub for now, with the shape a
  part's declaration has.
- **Every slice is kept**, each a file of its own in the Print card's file
  box until a person forgets it there.
- **`apothecary slicer slice` reaches made pieces** through the running
  server, so the command line and the page slice the same things.
- **A slicer seam record** is drafted on the governance branch beside the
  firmware seam, with the personal-data record's lines for the install and
  an amendment to the adoption-scope record naming OrcaSlicer (AGPL-3.0, run
  as a binary, never linked) beside OpenSCAD; a person ratifies them.
- Kept as built: a slice's record lasts as long as its file; a part
  declaring a nozzle the printer does not have is refused; a declared wall
  becomes enough nozzle-wide lines to reach it; a tolerance is reported, not
  passed to the slicer; parts are arranged on the bed and not turned; a
  kept file is named for its part.
