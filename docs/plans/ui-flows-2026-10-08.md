# The loops a person works in, through the page

*Decided with the owner on 2026-10-08: four loops a person goes round in the
page, each built out where pieces are missing, and each held end to end by
a browser test that goes round it at least twice. A loop that needs real
hardware is tested against the fakes and the simulated printer, and its
real run is a step of the bench checklist.*

## The four loops

1. **Designing a part.** Select a part, change its parameters, see the
   check, render, see the result, and go round again. This finishes the
   first iteration of the browser-editing spike
   ([part-editing-in-the-browser-2026-09-27.md](part-editing-in-the-browser-2026-09-27.md)):
   a cache of variants, so two tabs never race and returning to the
   defaults costs nothing; OpenSCAD's errors shown by line; the check
   debounced and a superseded render cancelled; the part panel starting from
   what is on disk, not the defaults.
2. **Editing a part's SCAD.** The spike's second and third iterations: every
   part gets controls from its SCAD's own parameters where OpenSCAD can
   list them; an editor in the page with a check as typing pauses and a
   render after a second of quiet, errors marked inline; a saved edit is a
   variant in git (a ref of the part's own, written with git's plumbing, so
   the working tree, the index and the checked-out branch are never
   touched), as decided on 2026-09-27. Parts whose geometry is Python show
   their generated SCAD read-only.
3. **Firmware.** Choose a sketch -- Arduino or Rust
   ([rust-2026-10-08.md](rust-2026-10-08.md)) -- build it, flash it, and see
   its hello in the board's Machine; change it and go round again. Tested
   against the scripted toolchains and a simulated board; flashing the
   bench's ESP32 is a bench step.
4. **A picture to a print.** A camera, Take picture, Find shapes, Make,
   adjust the piece, and a print job on printer_1; then a second picture
   and a second piece. Tested with the fake camera and the simulated
   printer.

## What "held" means

- One browser test per loop that goes round it at least twice through the
  page's own controls and ring cells, asserting what a person would see at
  each step, not only what the API answers.
- A walkthrough page per loop, its pictures taken by the test, so the docs
  show the loop as it is.
- Each step's words name the next step, as the pictures plan asked.
